# رسالة عاجلة إلى Claude — إصلاح عنوان Cloudflare Pages الجديد
التاريخ: 2026-10-27
المشروع: Home organization ideas
المستودع: Fadhel-docom/auto-blog

## المطلوب
أصلح بنفسك نشر العنوان الجديد `https://home-organization-ideas.pages.dev/` حتى يعرض الصفحة الرئيسية الحقيقية للموقع، لا صفحة الخطأ المخصصة ذات العنوان “This space needs reorganizing.”. لا تكتفِ بتقديم نصائح أو طلب لقطات شاشة إضافية؛ افحص ملفات المستودع وإعدادات البناء وسجل النشر، ونفّذ الإصلاح الآمن ثم تحقق من النتيجة.

## الأدلة المتاحة
- العنوان الجديد يعرض صفحة 404 الخاصة بالموقع بدل الصفحة الرئيسية. المستخدم أعاد إرسال محتوى صفحة الخطأ أكثر من مرة؛ هذه مشكلة متكررة ولم تُحل.
- مشروع Cloudflare Pages اسمه `home-organization-ideas`.
- إعدادات البناء التي ظهرت سابقًا: أمر البناء `hugo --baseURL https://home-organization-ideas.pages.dev/`، مجلد الإخراج `public`، المجلد الجذري فارغ، فرع الإنتاج `main`.
- سجل نشر سابق (ID: `87326bd1-d9b7-4a9a-b9e3-c0a01da8e02e`, commit `35c475d0f071bdee8d5b73f04a944bbb4e97458a`) ذكر: `No build command specified. Skipping build step.` ثم رفع 489 ملفًا مباشرة. هذا دليل مهم على أن ذلك النشر لم يشغّل Hugo، لكنه لا يثبت وحده حالة الإعدادات الحالية.
- المستودع يحتوي `layouts/index.html` و`content/_index.md`، ولذلك ينبغي أن ينتج بناء Hugo صحيح من جذر المستودع صفحة رئيسية.
- صفحة GitHub Pages الحالية هي `https://fadhel-docom.github.io/auto-blog/` وتعمل. يجب الحفاظ عليها كما هي.

## خطوات التشخيص والإصلاح المطلوبة
1. افحص آخر deployment في Cloudflare وسجله، وحدد هل نُفّذ أمر Hugo فعلًا وما هو مجلد الملفات المنشورة. لا تعتمد على لقطة إعدادات قديمة أو سجل نشر قديم.
2. تأكد أن Cloudflare متصل بالمستودع الصحيح `Fadhel-docom/auto-blog` وبفرع `main`، وأن Root directory فارغ، وأمر البناء `hugo --baseURL https://home-organization-ideas.pages.dev/`، ومجلد الإخراج `public`.
3. إذا كانت الإعدادات صحيحة لكن آخر نشر تخطّى البناء، شغّل إعادة نشر جديدة بعد حفظ/تصحيح الإعدادات. إن كان الاتصال أو الإعداد خاطئًا، أصلحه من لوحة Cloudflare إذا كانت صلاحيات الوصول متاحة.
4. تحقق بعد النشر من العنوان الإنتاجي والـ preview إن أمكن: يجب أن يعرض `/` الصفحة الرئيسية، وأن يعمل `/sitemap.xml` و`/robots.txt`، وألا تتحول الصفحة الرئيسية إلى قالب 404. تحقق أيضًا من عدم وجود روابط داخلية مكسورة بسبب الـ baseURL.
5. لا تغيّر قوالب الموقع لمجرد إخفاء 404، ولا تنشئ صفحة رئيسية وهمية، ولا تنقل المحتوى إلى مشروع آخر. أصلح سبب النشر.
6. إذا لم تكن لديك صلاحية Cloudflare، لا تدّعِ أن الإصلاح تم. قدّم للمستخدم خطوة واحدة محددة لازمة لتفعيل الوصول، ثم أكمل العمل بعد ذلك؛ لا تكرر عليه تعليمات إعداد البناء نفسها دون فحص جديد.

## قيود SEO غير قابلة للتفاوض
- لا تغيّر `baseURL` في `config.toml` الخاص بنشر GitHub Pages: قيمته الحالية `https://fadhel-docom.github.io/auto-blog/` وهي العنوان المستقر الذي يجب الحفاظ عليه خلال التشخيص.
- لا تحوّل canonical أو sitemap الإنتاجية إلى `pages.dev`، ولا تحذف أو تعطل نشر GitHub Pages، ولا تشترِ نطاقًا مخصصًا. المستخدم لا يريد شراء نطاق قبل أول دخل.
- أُضيف بالفعل فحص CI في `.github/workflows/site_deploy.yml` للتأكد من بقاء canonical وsitemap وrobots.txt على عنوان GitHub Pages ومنع تسرب عنوان Cloudflare المؤقت إلى إنتاج GitHub Pages. اجتاز آخر نشر GitHub Pages هذا الفحص؛ لا تتراجع عن هذا الحارس.

## التنسيق والتسليم
بعد الإصلاح، سجّل في غرفة العمليات تقريرًا قصيرًا يتضمن: السبب الجذري المؤكد، الملفات/الإعدادات التي تغيرت، رابط deployment الجديد، نتيجة فحص الصفحة الرئيسية وsitemap وrobots، وأي أثر محتمل على SEO. لا تقل إن المشكلة حُلّت إلا بعد اختبار فعلي للعنوان الجديد. بعد ذلك واصل مهام المشروع الأخرى بالتوازي دون تكرار العمل أو انتظار موافقة على كل تغيير منخفض المخاطر ومفيد.
